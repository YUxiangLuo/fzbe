跨学期实验归属改造草案（2026-09-07）。本文是下一批领域改造的设计，不会自动执行迁移。

当前约束：enrollments.student_id 全局唯一，experiment_status 只绑定 student_id；创建实验会因该学生已有任何实验而返回 already_exists。报告、成绩、导出和步骤事件列表通过当前 enrollments 推导班级。因此只给成绩查询增加 term_id 筛选无法恢复历史归属。

建议的业务语义是：同一账号可以跨学期修读；每次修读拥有独立实验及重做链；旧实验、报告和正式成绩固定归属原教学班级。转班只改变后续教学安排，不隐式迁移已经完成的记录。若产品仍要求一个账号只完成一次实验且成果随转班转移，应保留现有领域模型，把这一限制写入学期管理说明。

这两种语义对应不同迁移路径，当前首批修复没有改变这一业务规则。

建议引入独立的修读记录，而不是把易删除的当前班级成员关联直接作为历史主键：

| 对象 | 职责 |
| --- | --- |
| 当前班级成员关系 | 现有成员管理和未来任务分配 |
| teaching_enrollments | 学生在某班级、学期、教学任务中的修读，包含 active/archived 状态 |
| experiment_status.teaching_enrollment_id | 固定实验归属；一次修读可以包含初始实验与重做实验 |
| 重做 lineage | 父子必须属于同一学生、同一修读，沿用现有单链规则 |

首版可以维持每名学生只有一个 active 修读，避免同时引入多课程选择 UI。唯一性在修读任务内定义；完成一门课不会阻止下一学期创建新的修读和实验。跨学期按需加入第二个 active 修读时，API 和客户端再显式提供修读选择器。

涉及的代码边界：

- experiment 创建、active 查询、历史查询和重做接口：限定到修读，不再只按 student_id 获取最新记录。
- class-grades：成绩、报告、实验列表、步骤事件、CSV/ZIP 导出及教师/助教汇总统一使用固定归属，不能仅改总览页面。
- 班级删除：存在历史修读时转为归档或拒绝物理删除；当前 ON DELETE CASCADE 会移除 enrollments，不能作为历史记录保留策略。
- 成员删除/转班：对已开始修读使用显式结束/归档操作；在途任务的提交必须继续归入原修读。
- 学生端 store、repository、报告入口：以 active 修读为加载上下文，切换时作废旧请求和旧缓存。
- 评分政策：明确正式成绩是否需要发布快照；如果需要，历史成绩绑定评分政策版本，避免原班级权重后续修改改变已发布分数。

迁移采用分阶段兼容路径：

1. 扩展 schema：新增修读表、可空实验关联与索引，保持旧应用可运行。
2. 生成只读归属审计清单：区分可由可信业务记录确认的归属、只有当前班级线索的归属、没有选课关系的孤立实验。当前班级不是历史归属证据；迁移不自动把所有旧实验挂到当前班级。
3. 对确认的历史记录回填，并校验一个重做链归属一致。无法确认的记录保留 legacy 状态和待处理清单，不丢弃。
4. 部署兼容读写版本，新建修读必须显式绑定；所有成绩与导出统一使用关联字段，legacy 查询独立说明其限制。
5. 在停止旧写入后再次审计，确认没有新产生的未归属实验，然后再决定收紧可空字段或移除旧查询路径。

必须具备的数据库与浏览器回归场景：

- 学期 A 的报告已评分，学生进入学期 B 后，A 的班级成绩和导出保持不变，B 可以创建新实验。
- A 被驳回的重做链不能自动接入 B 的实验。
- 活动修读转班时，旧的训练/报告请求不能写入新的修读。
- 班级归档与权重变更不隐式改写已发布历史结果。
- 迁移可重复执行；中断后继续；含有归属不明确的旧记录时不猜测、不丢数据。
- 新旧前后端的阶段性组合有明确支持范围，旧客户端不会读到错误修读的“最新实验”。
