# 生产计划（MPS）公式契约

本页是前端 `productionPlanCalculation.ts` 与后端
`src/modules/experiments/experiments.schema.ts` 的唯一公式依据。后端在保存实验
和提交报告时会按本页公式逐格复算学生提交的计划表，任一单元格不一致即返回
`PRODUCTION_PLAN_MISMATCH`。

名词与公式均以《虚拟仿真系统需求确认文档-最终版20241226》第五章
“生产计划的制定”为准。文档中的表格是本公式在 **期初库存 = 0、产能不受限**
时的特例，这两个参数取文档值时每一格都与文档一致。

## 字段与文档名词对照

| 字段 | 文档名词 | 说明 |
| --- | --- | --- |
| `demand_forecast` | 需求量 / 需求预测结果 | `round(预测结果)` |
| `safety_stock` | 安全库存 | 第一个月为 0，其后 `round(z × σ)` |
| `forecast_quantity` | 预测量 | 需求预测结果 + 安全库存（5.4） |
| `planned_production` | 投入量 | 预测量 − 上月库存量 + 上月缺货量（5.5） |
| `beginning_inventory` | 上月库存量 | 第一个月为期初库存 |
| `production_output` | 产出量 | 上月投入量，受产能约束（5.2，提前期 1 个月） |
| `ending_inventory` | 库存量 | 余额的正部分 |
| `stockout` | 缺货量 | 余额的负部分（欠交，连续缺货时含上期未补部分） |
| `service_level` | 服务水平 | 1 − 缺货量 / 实际需求量，在 0 处截断（5.3） |

## 递推公式（第 t 期，t 从 1 起）

```
需求量_t   = max(0, round(预测结果_t))
安全库存_t = t == 1 ? 0 : max(0, round(z × σ_t))
预测量_t   = 需求量_t + 安全库存_t
产出量_t   = t == 1 ? 需求量_1 : max(0, min(投入量_{t-1}, 产能))
余额_t     = 余额_{t-1} + 产出量_t − 需求量_t          （余额_0 = 期初库存）
上月库存量_t = max(0, 余额_{t-1})
库存量_t   = max(0, 余额_t)
缺货量_t   = max(0, −余额_t)
投入量_t   = max(0, 预测量_t − 余额_{t-1})
           = max(0, 预测量_t − 上月库存量 + 上月缺货量)
服务水平_t = 需求量_t > 0 ? max(0, 1 − 缺货量_t / 需求量_t) : 1
```

- 期初库存 = 0 时第一个月自然满足文档的标准化：产出量 = 需求量，
  库存量 = 缺货量 = 0，投入量 = 预测量。
- 物料守恒恒等式：期初库存 + Σ产出量 − Σ需求量 = 期末余额。前端可用它自检。
- `period` 从 1 连续递增，`period_label` 固定为 `期 N`。
- 产能场景（紧张 / 正常 / 充足）与自定义产能的取值规则不变，见
  `buildProductionCapacityScenarios`。
- 目标服务水平与安全系数 z 仍只接受 0.9/1.28、0.95/1.65、0.99/2.33 三组。

## 与旧实现的差异

旧实现把缺货按丢失销售处理（不进入下期余额），却又把上月缺货量加进投入量，
导致 Σ产出 − Σ需求 ≠ 期末库存。现行公式采用带符号余额：上月缺货由本期产出优先补
发，这与文档 p.121–122 “上月库存量……能够在当前月直接用于满足需求”“上月缺货量
……会在当前月被优先考虑”的描述一致。

## 前端要求

前端必须按本页公式计算并提交全部字段（含 `forecast_quantity`）。缺少字段或任一
单元格不一致的计划表都会被拒绝，不存在旧格式兼容路径；前端与后端需同一发布。
