首批优先级修复：异步失败回滚、评分权重并发和成绩汇总错误表达。

状态同步现在只允许失败请求回滚其仍拥有的乐观状态。新的本地编辑、服务端状态更新、新实验和直接 hydration 均不会被旧请求失败覆盖。单独失败、没有后续更新时仍保留原来的回滚行为。

评分权重更新在同一个事务连接内读取 FOR UPDATE 快照、合并和验证部分字段、写入、读回并提交。第二个编辑者在获取锁后重新验证；如果它的补丁基于最新权重已不再满足总和 100，就沿用 invalid_weight_total 返回，不写入。没有增加数据库 schema 或修改现有评分公式。

教师/助教成绩汇总仍返回 data 数组。每个班级新增：

| 字段 | 成功 | 失败 |
| --- | --- | --- |
| load_status | ready | error |
| load_error | null | missing_grading_policy / query_failed |
| 人数、各提交状态数量 | 实际数值，包括真实的 0 | null |
| average_score | 数字或 null | null |

失败班级保留身份信息，服务端记录诊断日志。前端显示对应错误和重新加载按钮；所有图表只统计成功班级，并在存在失败时明确说明统计范围。一次重试重新读取当前学期的班级汇总，继续使用既有请求取消和迟到结果处理。

前端可读取旧后端没有 load_status 的正常汇总，所以部署应先发布前端，再发布后端。旧页面不会识别新的失败状态，后端更新后应刷新已打开的教师/助教页面。OpenAPI 和生成的前端类型已同步。

回归覆盖了失败请求的四类后续状态、无后续更新的原有回滚路径、锁内权重重新校验、缺少权重、写入/提交失败释放连接、教师和助教部分汇总失败、真实空班级与失败的区别、失败班级排除出图表及重试恢复。

跨学期领域模型未在本批迁移；该方向现已按用户决定取消，历史草案见 [teaching-enrollment-design.md](./teaching-enrollment-design.md)。

验证结果（项目固定 Bun 1.4.0）：后端 1097 项单测、前端 808 项单测全部通过；两端类型检查、测试清单、正式前端构建、OpenAPI lint 和生成 API 类型一致性检查通过。Python 模型未改动，本批没有重跑 Python 或全角色 E2E。

一次性真实 MariaDB 复测了两个重叠部分权重更新：最终总和 100，至少一个不再合法的更新被拒绝；测试库已删除。浏览器使用 agent-browser，在真实教师页面注入成功、查询失败、缺少权重三类 API 响应，检查失败卡片、图表排除及点击重试后的恢复；没有通过浏览器改动业务库。
